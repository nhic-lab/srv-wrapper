# Daemon-fed sudo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let `srv exec --sudo`, `srv exec-many --sudo` and `srv session start --sudo` run as root on servers where the human enabled sudo in the dashboard, with the daemon feeding the Keychain password to `sudo` so the agent never sees it and nothing is written to the box's sudoers.

**Architecture:** A per-server `sudoAllowed` switch and optional `<id>:sudo` Keychain entry live daemon-side. `exec` rewrites the command as `sudo -S -k -p '' -- sh -c 'exec </dev/null; …'` and writes the password to the channel's stdin; sessions prime sudo's own timestamp cache via `sudo -v` driven by a sentinel-watching state machine. All sudo-specific string handling lives in a new `src/daemon/sudo.ts` so the leak guards are unit-tested in isolation.

**Tech Stack:** TypeScript, Node, `ssh2`, better-sqlite3, Express, vitest, vanilla JS dashboard.

**Spec:** `docs/superpowers/specs/2026-10-28-sudo-design.md`

## Global Constraints

- The sudo password never appears in: the CLI process, the command string handed to `client.exec`, `runs.command`, `runs.output`, any broadcast, or daemon stderr.
- Additive SQLite migrations only, using the existing `PRAGMA table_info` + `ALTER TABLE ADD COLUMN` pattern.
- `registry.upsert` lists columns explicitly; an edit that omits `sudoAllowed`/`hasSudoSecret` keeps the stored values.
- Test doubles: real `Registry`/`LogStore` on temp SQLite files; fake `connectFn` and fake Keychain `exec`. Never mock SQLite.
- Keychain account for the sudo secret is exactly `<serverId>:sudo`, same service `srv-wrapper`.
- Exact wrapper for exec: `sudo -S -k -p '' -- sh -c '<single-quoted: exec </dev/null; COMMAND>'`.
- Session priming line: `sudo -k; sudo -p '__srv_sudo''_<uuid>__' -v; echo '__srv_done''_<uuid>__'$?` + `\n`. Sentinels are split in the written text and matched joined.
- Refusal messages: `sudo is not enabled for <id>` and `sudo error: no sudo password stored for <id>`. Priming failure: `sudo error: authentication failed`; priming timeout (15 s): `sudo error: timed out waiting for sudo prompt`.
- Dashboard: `.chip.sudo` uses `--sunbird` background with `--on-sunbird` text (never `--basalt`).
- Commits: no co-author line (user rule).

## Review Focus

1. Commands containing single quotes, `$`, backticks or newlines must survive the `sh -c` quoting byte-for-byte → test in Task 4.
2. The priming sentinels arriving split across two `data` chunks must still be matched → test in Task 4.
3. The PTY echo of the priming line (containing the *broken* sentinel) must not trigger the password write → test in Task 4.
4. A priming failure or timeout must close every hop client and leave no session registered → test in Task 6.
5. Toggling sudo off on edit must delete only the `:sudo` entry, leaving the login secret and the record's other fields intact → test in Task 9.

### Task 4: `sudo.ts` — quoting, exec wrapper, session primer

**Files:**
- Create: `src/daemon/sudo.ts`
- Test: `test/daemon/sudo.test.ts`

**Interfaces:**
- Produces:
```ts
export class SudoError extends Error { name = 'SudoError' }   // passed through unsanitized by the socket server
export function shellSingleQuote(s: string): string            // 'a'\''b'
export function buildSudoExecCommand(command: string): string  // see Global Constraints
export interface PrimerResult { writePassword: boolean; done?: { ok: boolean }; passthrough: string }
export interface SudoPrimer { readonly commandLine: string; feed(chunk: string): PrimerResult }
export function createSudoPrimer(token?: string): SudoPrimer   // token defaults to randomUUID()
```
`feed` accumulates chunks. It reports `writePassword: true` exactly once, the first time the joined prompt sentinel `__srv_sudo_<token>__` appears in the accumulated text. It reports `done` when `__srv_done_<token>__<digits>\n` appears; `ok` is `digits === '0'`; `passthrough` is everything after that newline. Before `done`, `passthrough` is always `''`.

- [ ] **Step 1: Write the failing tests**

```ts

  it('wraps with the leak guard and -k, and never alters the command bytes', () => {
    const cmd = `echo 'it'"'"'s $HOME \`date\`\nls`
    const out = buildSudoExecCommand(cmd)
    expect(out.startsWith(`sudo -S -k -p '' -- sh -c '`)).toBe(true)
    expect(out).toContain(`exec </dev/null; `)
    expect(out).toBe(`sudo -S -k -p '' -- sh -c ${shellSingleQuote('exec </dev/null; ' + cmd)}`)
    expect(shellSingleQuote(`it's`)).toBe(`'it'\\''s'`)
  })
})

describe('createSudoPrimer', () => {
  const token = 'abc'
  it('writes the sentinels split in the command line so the PTY echo never contains them joined', () => {
    const p = createSudoPrimer(token)
    expect(p.commandLine).toBe(`sudo -k; sudo -p '__srv_sudo''_abc__' -v; echo '__srv_done''_abc__'$?\n`)
    expect(p.commandLine).not.toContain('__srv_sudo_abc__')
    expect(p.commandLine).not.toContain('__srv_done_abc__')
  })
  it('does not write the password in response to the echoed command line', () => {
    const p = createSudoPrimer(token)
    expect(p.feed(p.commandLine).writePassword).toBe(false)
  })
  it('writes the password exactly once when the joined prompt sentinel appears, even split across chunks', () => {
    const p = createSudoPrimer(token)
    expect(p.feed('__srv_su').writePassword).toBe(false)
    expect(p.feed('do_abc__').writePassword).toBe(true)
    expect(p.feed('__srv_sudo_abc__').writePassword).toBe(false)
  })
  it('reports done ok with passthrough after the done line, without ever asking for the password on NOPASSWD boxes', () => {
    const p = createSudoPrimer(token)
    const r = p.feed('__srv_done_abc__0\r\nuser@host:~$ ')
    expect(r.writePassword).toBe(false)
    expect(r.done).toEqual({ ok: true })
    expect(r.passthrough).toBe('user@host:~$ ')
  })
  it('reports done not-ok on a non-zero code', () => {
    const p = createSudoPrimer(token)
    p.feed('__srv_sudo_abc__')
    expect(p.feed('Sorry, try again.\n__srv_done_abc__1\n').done).toEqual({ ok: false })
  })
})
```
